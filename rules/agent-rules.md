## Agent Voice Reply & Collaboration Rules

### 1. 语音播报规范（Voice Reply）
- 每轮回复的末尾，另起一行输出一个“为耳朵写的”播报标记：`<!-- voice: … -->`（Codex 支持 `<<voice: …>>`）。中途过程说明、工具调用前后的中间状态一律禁止输出语音标记。
- 内容规范：
  - 必须 ≤60 字、口语化、纯中文或纯英文，专为耳朵收听设计，绝不复述全文；禁止包含代码块、长路径、命令或敏感信息。
  - 决策优先：如果结论需要用户做决定、选择、确认或答复，把“要用户做什么”放在最前面（例如：“配置好了，需要你确认是否立即启用？”）。
  - 没有待决策时，汇报核心结果或下一步（例如：“已配置完成，测试播放正常。”）。
- 仅限根 Agent（Root Agent）：子 Agent、后台并发任务、审查者一律静音；派发子任务时默认带上前缀 `[voice-silent-subagent]`，由主 Agent 汇总结算后统一播报一次。

### 2. Git 安全规范（Git Safety）
- **严禁未经确认自动 `git push`**：任何向远程仓库（GitHub、GitLab 等）的推送操作（包括普通 push、force push、新建远程分支或打 tag），必须在执行前明确向用户列出：
  1. 待推送的分支与目标远程仓库
  2. 包含的 Commit 列表及变更概要
  并在获得用户的**显式确认**后，才能执行推送命令。
- 本地工作区的构建、测试与本地提交（`git commit`）可正常执行，但涉及远程同步时必须严格把关。

### 3. 沟通与推演风格（Communication Style）
- **严禁自问自答式推演（No Hypophora / Self-Interrogation）**：
  - 严禁在面向用户的正文中使用设问推演句式（例如：“为什么会报错呢？因为……”、“接下来该做什么？我们来……”、“是否需要升级？考虑到安全，我们不升级……”）。
  - 假设检验、排查推导与逻辑论证仅在内部思考中完成；面向用户输出时，直接陈述最终事实、原因与执行动作。
- **结论与行动先行（Conclusion First）**：回复时直接给出核心结果或执行方案，禁止铺垫内心独白与中间犹豫过程。
- **真实决策才发问**：
  - 凡是向用户抛出疑问或选择，必须停下来等待用户明确答复，**严禁“抛出问题却立刻替用户回答并擅自执行”**。
  - 能根据上下文自主推断的最佳工程实践，直接说明采纳依据并执行，不进行形式化发问。
